PART 0
도구 소개 — 30초

파일 2개가 전부다

파일무엇
nsx-collector.py수집기 본체. 이건 건드릴 일 없다
nsx-collector.conf 내가 채우는 것. 이 자료의 Part 1~4 가 전부 이 파일 이야기다

장비에 이 두 개만 올리면 된다. 설치할 것이 없다 — 파이썬 표준 라이브러리만 쓴다.

장비를 알아서 구분한다

같은 파일인데 NSX Edge 에서는 Edge 메뉴가, ESXi 에서는 ESXi 메뉴가 나온다. 잘못된 명령을 고를 일이 없다.

무엇을 모으나

장비수집 항목
NSX Edge · LB T1 서비스 인터페이스 패킷 캡처
· VPC T1 업링크 패킷 캡처
· T0 업링크 패킷 캡처
· 인터페이스 · CPU · 메모리 카운터
· 방화벽 연결 테이블, LB 상태 · 풀
ESXi · DFW 적용 전(pre) 패킷 캡처
· DFW 적용 후(post) 패킷 캡처
· DFW 플로우 테이블 · 룰 · pass/drop 카운터
· 스위치포트 · 업링크 NIC 카운터
왜 이걸 쓰나 — 한 줄로

세션 테이블 같은 것은 지나가면 영영 못 얻는다. 증상이 있는 그 순간에 무엇을 떠야 하는지를 미리 정해 두고 한 번에 도는 것, 그게 전부다.

올리고 실행하기

scp nsx-collector.py nsx-collector.conf root@<장비>:/root/nsxc/

ssh root@<장비>
cd /root/nsxc
python3 nsx-collector.py          # 메뉴가 뜬다
NSX Edge 는 반드시 root 로

admin 으로 들어가면 NSX CLI 셸이라 python3 가 실행되지 않는다.

PART 1
설정 채우기 ①
공통 항목
Edge · ESXi 어느 쪽이든 똑같이 해당되는 항목.

먼저 알아야 할 규칙 3가지

규칙 1 — 한 파일로 두 장비를 다 쓴다

이 파일 하나에 Edge 용 칸과 ESXi 용 칸이 같이 들어 있다. 지금 장비가 필요로 하는 것만 채우고 나머지는 그냥 비워 둔다.

규칙 2 — 빈 값은 "안 함"이다

비워 두면 "그건 수집하지 않는다"는 뜻이다. "조건이 없으니 전부"가 아니다.
딱 하나 예외가 캡처 필터다 — 그건 Part 4 에서 따로 다룬다.

규칙 3 — 윈도우 편집기로 열지 말 것

메신저로 붙여넣거나 윈도우 메모장으로 저장하면 줄바꿈이 바뀌어 실행을 거부한다. 장비에서 vi 로 고치는 게 가장 안전하다.

공통 항목 — 5개뿐

키무엇안 채우면
CASE_ID 선택 케이스 번호. 화면에만 표시된다표시 안 함
TAG 선택 결과 파일 이름에 들어갈 짧은 이름호스트명을 쓴다
OUT 선택 결과가 쌓일 곳 Edge /var/dump/nsx-collect
ESXi /tmp/nsx-collect ← 위험
MIN_FREE_MB 선택 이 용량 아래로 떨어지면 자동 정지Edge 1024 / ESXi 64
ESXi 라면 OUT 을 꼭 바꾼다

ESXi 의 /tmp 는 약 250MB 짜리 메모리 디스크다. 캡처를 조금만 돌려도 꽉 찬다.

OUT="/vmfs/volumes/<데이터스토어>/nsxc"

df -h 로 여유부터 본다. 데이터스토어 이름에 공백이나 괄호가 든 것은 피한다 (예: datastore1 (1)).

얼마나 오래 · 얼마나 크게

키기본설명
패킷 캡처에만 적용
CAP_SECS600몇 초 동안 캡처할지
CAP_FILESIZE100파일 하나당 MB
CAP_FILECOUNT5파일 몇 개까지. 넘으면 오래된 것부터 덮어쓴다
CAP_SNAPLEN전체패킷당 저장할 바이트. 헤더만 보면 되면 "128" 등으로 줄인다
상태 · 세션 수집에만 적용
INTERVAL30몇 초마다 한 번씩 뜰지
DURATION1200총 몇 초 동안 뜰지
용량 계산은 곱셈 하나면 된다

CAP_FILESIZE × CAP_FILECOUNT = 캡처 한 지점이 쓰는 최대 용량

기본값이면 100 × 5 = 500MB. 캡처 지점이 2곳이면 1GB. 남은 디스크와 비교해 보고 정한다.

처음 연습할 때는 작게
CAP_SECS=30
CAP_FILESIZE=10
CAP_FILECOUNT=2      # 최대 20MB 로 끝난다
PART 2
설정 채우기 ②
NSX Edge
Edge 에서 작업할 때만 읽으면 된다.

필수는 딱 하나 — 어디서 캡처할지

아래 둘 중 최소 하나만 채우면 된다. 둘 다 채워도 된다.

키무엇
LIF_LBT1_SVC 필수 LB T1 의 서비스 인터페이스 UUID
LIF_VPCT1_UPLINK 필수 VPC T1 의 업링크 인터페이스 UUID
이게 비어 있으면 캡처가 아예 시작을 안 한다

메뉴에서 start 를 눌러도 캡처 항목이 idle 로만 표시되고 아무 일도 일어나지 않는다. 카운터와 세션은 잘 도는데 캡처만 안 되는 모습이라 "패킷 덤프가 안 된다"로 보인다.

실제로 가장 많이 겪는 문제다. Part 6 에 실제 사례가 있다.

찾는 방법 — 명령 2개

su admin -c "get logical-routers"
   # 라우터 목록이 나온다. LB 용 T1 과 VPC 용 T1 의 UUID 를 확인

su admin -c "get logical-router <위에서 찾은 UUID> interfaces"
   # 인터페이스 목록에서 Port-type 을 본다

      Port-type: service   →  이 UUID 를  LIF_LBT1_SVC     에
      Port-type: uplink    →  이 UUID 를  LIF_VPCT1_UPLINK 에

둘 다 조회 명령이다. 장비 설정을 바꾸지 않는다.

Active 인 Edge 에서 해야 한다

T1 은 보통 Edge 2대가 Active / Standby 로 나눠 갖는다. Standby 쪽에서 캡처하면 패킷이 0건이다. 트래픽이 그쪽으로 안 가기 때문이다.

어느 쪽이 Active 인지는 메뉴의 check 가 알려 준다(Part 5). 캡처 전에 반드시 확인한다.

T0 는 비워 두는 게 맞다

키설명
LIF_T0_UPLINK 비워 둔다. 비워 두면 도구가 이 장비의 T0 를 알아서 찾아 업링크 전부에서 캡처한다(보통 2개)
CAPTURE_T0 "yes" 로 하면 start 에 T0 캡처도 포함된다. 기본은 제외 — T0 는 사이트로 들어오는 트래픽 전부라 너무 시끄럽다.
필요하면 메뉴 대신 cap-t0 로 한 번만 돌리면 된다

선택 — 채우면 더 정확해지는 것들

안 채워도 캡처는 된다. 채우면 필터가 자동으로 만들어져 쓸데없는 패킷이 줄어든다.

키무엇
VIPLB 가상 서버 IP
NAT_IP DNAT 되기 전의 공인 주소 — 아래 설명 참조
LB_SNAT_IPLB 가 백엔드로 나갈 때 쓰는 주소
CLIENT_IP클라이언트 주소 또는 대역
SVC_PORT클라이언트 → VIP 포트 (예: 443, 1812)
NODE_PORTLB → 백엔드 포트 (예: 80, 31820)
NAT_IP 를 빠뜨리면 VPC T1 캡처가 0건이 된다

VPC T1 업링크는 NAT 되기 전 구간이다. 그래서 그곳에는 VIP 주소가 아예 나타나지 않는다. VIP 로만 필터를 걸어 두면 당연히 아무것도 안 잡힌다.

랩 실측: NAT_IP 를 넣기 전 0건 → 넣은 뒤 370건.

선택 — 상태도 같이 볼 라우터

키설명
T1_LB_SR_UUID
T1_VPC_SR_UUID
T0_SR_UUID		 여기 적은 라우터의 카운터 · HA 상태를 같이 수집한다.
라우터 하나당 한 번 뜰 때마다 약 2.5초가 걸리니 필요한 것만 적는다
LB_UUID · LB_POOL_UUIDSLB 상태 · 풀 · 가상서버를 같이 수집

# --- 공통 (Part 1) ---

CAP_SECS=300

# --- 필수: 어디서 캡처할지 ---
LIF_LBT1_SVC="11111111-2222-3333-4444-555555555555"
LIF_VPCT1_UPLINK="66666666-7777-8888-9999-aaaaaaaaaaaa"

# --- 선택: 필터를 정확하게 ---
VIP="10.1.1.10"
NAT_IP="203.0.113.10"        # ← 빠뜨리면 VPC T1 이 0건
LB_SNAT_IP="10.1.1.20"

NODE_PORT="80"

# --- 선택: 상태도 같이 ---
T1_LB_SR_UUID="bbbbbbbb-cccc-dddd-eeee-ffffffffffff"
T1_VPC_SR_UUID="12345678-90ab-cdef-1234-567890abcdef"
PART 3
설정 채우기 ③
ESXi
ESXi 호스트에서 작업할 때만 읽으면 된다. Edge 보다 훨씬 단순하다.

필수는 딱 하나 — 어느 VM 을 볼지

키무엇
WORKER_VMS 필수 대상 VM 이름. 여러 개면 공백으로 구분

찾는 방법 — 명령 1개

vim-cmd vmsvc/getallvms
   # 여기 나오는 이름을 그대로 적는다

WORKER_VMS="web01 web02"
이 호스트에 없는 VM 을 적어도 된다

없는 VM 은 "이 호스트에 없다"고 알려 주고 건너뛴다. 그래서 여러 호스트에 같은 설정 파일을 뿌려도 된다 — 각자 자기 호스트에 있는 VM 만 수집한다.

이름에 공백이 든 VM 은 못 쓴다

공백으로 구분하는 목록이라 담을 수 없다. 도구가 목록에서 빼고 이유를 알려 준다. 괄호가 든 이름(SupervisorControlPlaneVM_(2))은 정상 처리된다.

나머지 2개 — 선택

키설명
WORKER_VNIC 선택 비워 두기를 권장. 비우면 그 VM 의 모든 vNIC 을 본다. 특정 vNIC 만 보고 싶을 때만 적는다
UPLINK_NICS 선택 물리 NIC 카운터를 같이 볼 때. "vmnic0 vmnic1"

완성 예시 — ESXi

# --- 공통 (Part 1) ---
CASE_ID="ISCPSR-12345"
TAG="esxi02"
OUT="/vmfs/volumes/ds02/nsxc"      # ← /tmp 쓰지 말 것
CAP_SECS=300

# --- 필수: 어느 VM ---
WORKER_VMS="web01 web02"

# --- 선택 ---
WORKER_VNIC=""                     # 비움 = 모든 vNIC
UPLINK_NICS="vmnic0 vmnic1"

# --- 무엇을 잡을지 (Part 4) ---
FILTER="tcp port 80"
ESXi 는 설정이 이게 전부다

Edge 처럼 UUID 를 찾아 넣을 일이 없다. VM 이름만 정확하면 된다.

PART 4
설정 채우기 ④
무엇을 잡을까
캡처 대상을 좁히는 방법. Edge · ESXi 공통.

방법은 두 가지, 하나만 고르면 된다

방법 1 — FILTER 에 직접 쓴다 (권장)

tcpdump 표현식을 그대로 쓴다. 이걸 쓰면 다른 모든 설정보다 우선한다.

FILTER="tcp port 80"
FILTER="host 10.1.1.10 and (udp port 1812 or udp port 1813)"
FILTER="(host 10.1.1.10 or host 10.1.1.11) and not tcp port 22"
FILTER="net 10.1.1.0/28 and udp"
방법 2 — 칸을 채운다 (FILTER 를 비웠을 때만)
키무엇예
HOSTS주소"10.1.1.10 10.1.1.0/28"
PROTO프로토콜"udp" · "udp tcp"
PORTS포트"1812 1813"

Edge 라면 Part 2 의 VIP · NAT_IP · SVC_PORT 등도 여기에 함께 쓰인다. 도구가 캡처 지점마다 알맞은 필터를 따로 만들어 준다.

# 실제로 만들어지는 필터 (Part 2 예시 설정 기준)

LB T1    ((host 10.1.1.10) and (tcp and port 443))
         or ((host 10.1.1.20) and (tcp and port 80))
         or (icmp and (host 10.1.1.10 or host 10.1.1.20))

VPC T1   (host 10.1.1.10 or host 203.0.113.10) and ((tcp and port 443) or icmp)

지점마다 봐야 할 주소가 다르다는 것을 도구가 알아서 처리한다 — LB T1 은 VIP 와 SNAT 주소를, VPC T1 은 NAT 전 주소를 본다.

꼭 기억할 함정 2가지

① and 와 or 는 우선순위가 같다 — 괄호를 쓴다

수학처럼 and 가 먼저 계산되지 않는다. 왼쪽부터 순서대로 읽는다.

내가 의도한 것    a or (b and c)
실제로 해석되는 것  (a or b) and c     ← 다르다!

해결:  괄호를 직접 쓴다
② 전부 비우면 모든 패킷을 잡는다

FILTER 도 비우고 칸도 다 비우면 그 인터페이스의 패킷을 전부 잡는다. 디스크가 순식간에 찬다. 의도한 게 아니면 뭐라도 채운다.

넣고 나서 반드시 확인

메뉴에서 config 를 누르면 실제로 만들어진 필터식을 보여 준다. 문법이 틀리면 시작 전에 걸러 준다. 눈으로 한 번 보는 습관을 들인다.

Edge 에서 수집을 돌렸는데 카운터와 세션은 도는데 캡처만 idle 이었다.

  none

원인: 설정 파일의 LIF_LBT1_SVC 와 LIF_VPCT1_UPLINK 가 둘 다 비어 있었다. VIP 와 NAT_IP 도 <VIP>, <NAT_IP> 자리표시자 그대로였다.

해결: 값을 채운 설정으로 다시 돌리니 30초에 14,455 패킷이 잡혔다.

카운터·세션이 잘 도는 것에 속으면 안 된다. 그것들은 캡처 지점이 필요 없어서 설정이 비어 있어도 잘 돈다.

NSX Edge — 두 가지 셸이 있다

Edge 에는 리눅스 셸과 NSX CLI 두 가지가 있고, 명령이 갈린다.

셸어떻게 들어가나여기서 치는 것
리눅스 셸ssh root@<edge> tcpdump, ip link, timeout
NSX CLIssh admin@<edge> get ..., set capture session ...
root 로 들어가서 NSX CLI 명령을 치는 방법

도구는 root 셸에서 su admin -c 로 NSX CLI 명령을 던진다. 이 방식이면 셸을 오가지 않아도 되고, 스크립트로 묶기도 쉽다.

su admin -c "get interfaces"
su admin -c "get logical-routers"

이 별첨의 Edge 명령은 전부 이 형태로 적는다. admin 셸에 직접 들어가 있다면 su admin -c "..." 를 빼고 안쪽 명령만 치면 된다.

admin 셸에서는 리눅스 명령이 안 된다

admin 으로 로그인하면 NSX CLI 셸이라 tcpdump, python3, ls 같은 것이 % Command not found 로 거부된다. 패킷 덤프는 반드시 root 셸에서 해야 한다.

ESXi — 셸 하나뿐

ssh root@<esxi>

모든 명령을 여기서 친다. 다만 ESXi 의 timeout 은 문법이 일반 리눅스와 다르다 — D · G 장에서 다룬다.

결과를 어디에 남길 것인가

원리 — 인터페이스를 직접 뜰 수 없다

NSX Edge 의 논리 인터페이스는 tcpdump 로 직접 지정할 수 없다. 그래서 span 미러를 만들어 span-N 이라는 가상 인터페이스를 띄우고, 거기에 tcpdump 를 붙인다.

  <LIF-UUID> ──(미러)──▶ span-0 ──▶ tcpdump

3단계로 한다

D-1  ·  NSX CLI
① span 미러 생성
su admin -c "set capture session 0 interface <LIF-UUID> direction dual"

0 은 세션 번호(0~3). dual 은 양방향.

생성되면 span-0 인터페이스가 리눅스 쪽에 나타난다. 확인:

ip link show span-0
최대 10초쯤 기다려야 할 수 있다

도구도 1초 간격으로 10번까지 확인하고, 안 뜨면 세션을 지우고 실패 처리한다 (미러를 남기지 않기 위해). 안 뜨면 LIF UUID 를 다시 확인한다.

D-2  ·  리눅스 셸 (root)
② tcpdump 로 받기 ★
timeout -s INT 300 tcpdump -nei span-0 \
  -Z root \
  -C 100 -W 5 \
  -w /var/dump/manual/pcap/10-lbt1svc-$(date +%H%M%S).pcap \

옵션왜 필요한가
-Z root 반드시 넣는다. tcpdump 는 기본적으로 권한을 낮추는데, 그러면 링 버퍼의 다음 파일을 못 만든다
timeout -s INT 300 300초 뒤 INT 시그널로 정상 종료. 그래야 마지막 파일이 온전하다
-C 100 -W 5 파일당 100MB, 5개까지 = 최대 500MB. 넘으면 오래된 것부터 덮어쓴다
-nein 이름해석 안 함 · e L2 헤더 표시 · i 인터페이스
-s 128(선택) 패킷당 128바이트만. 헤더만 볼 때 용량 절약

남겨두면 안 된다

미러는 계속 패킷을 복사한다. 운영 장비에 남기면 부하가 된다. 도구는 tcpdump 가 어떻게 끝나든 finally 로 반드시 지운다. 손으로 할 때는 잊기 쉬우니 먼저 메모해 둘 것.

D-5. 어느 LIF 를 뜰 것인가

지점무엇이 보이나세션 번호 예
LB T1 서비스VIP 로 들어온 트래픽, LB → 백엔드0
VPC T1 업링크NAT 이전 트래픽 — VIP 가 안 보인다1
T0 업링크사이트로 들어오는 전부. 매우 시끄럽다2, 3
캡처가 0건일 때 — 순서대로 본다
  1. 이 Edge 가 Standby 인가 — B-5 의 HA 상태 확인. Standby 면 0건이다
  2. 그 시간 동안 매칭되는 트래픽이 실제로 있었나
  3. 필터가 이 지점에 안 맞나 — VPC T1 업링크는 NAT 이전이라 VIP 가 절대 안 나타난다. 공인/NAT 주소로 걸거나 필터를 비운다
이 세 지점은 one-arm LB 기준이다 — inline 이면 다르다

도구의 Edge 캡처 지점은 one-arm LB(LB 가 T1 의 서비스 인터페이스에 붙고 SNAT 이 필수인 구조)를 전제로 만들어졌다.

지점one-arminline
T0 업링크○○ 그대로
T1 업링크 (클라이언트 쪽)○○ 그 T1 업링크를 LIF_VPCT1_UPLINK 에
LB 서비스 IF○해당 없음 — 서비스 IF 가 없다
T1 다운링크 (백엔드 쪽)해당 없음 캡처 불가 — 도구의 캡처 지점에 없다

inline 에서는 다운링크 공백을 ESXi 쪽으로 메운다 — 백엔드 VM 의 DFW pre/post 가 "LB 가 보낸 패킷이 서버에 도착하는 지점"을 보여 준다 (부록 G). 결국 T0 업링크 · T1 업링크 · ESXi pre · ESXi post 네 지점이면 구간 판정이 된다.

또한 inline 은 SNAT 이 선택이라 LB_SNAT_IP 가 비기 쉽다. 그러면 단순 필드로 만든 필터에서 LB→백엔드 구간 절이 통째로 빠진다. inline 이면 FILTER 를 직접 쓰는 편이 안전하다.

FILTER="(host <VIP> or host <백엔드IP>) and tcp port <포트>"

LIF_VPCT1_DOWNLINK 는 캡처는 안 되지만 방화벽 연결 테이블은 수집된다(부록 C). inline 이면 이 값은 꼭 채운다.

T0 는 A/A — 모든 Edge 에서 동시에 떠야 한다

T0 는 보통 Active/Active 라 트래픽이 노드마다 나뉜다. 한 노드만 뜨면 절반만 보인다. 그리고 T0 업링크는 보통 2개라 노드당 2개를 떠야 한다.

ESXi — 패킷 덤프
도구의 cap-pre · cap-post. DFW 적용 전/후를 같은 vNIC 에서 뜬다.

원리 — 전과 후를 같이 떠서 대조한다

  vNIC ──▶ [ pre ] ──▶ DFW 룰 평가 ──▶ [ post ] ──▶ 스위치

  pre 에는 있는데 post 에 없다  =  DFW 가 막았다

이것이 ESXi 캡처의 핵심이다. 추정이 아니라 증거가 된다.

먼저 알아야 할 것 — pktcap-uw 에는 BPF 필터가 없다

tcpdump 처럼 'host A and port B' 같은 표현식을 못 쓴다. --ip, --tcpport 같은 개별 옵션만 있고 or 조합이 안 된다.

그래서 방법이 둘로 갈린다 — G-1(옵션만) 또는 G-2(tcpdump-uw 로 파이프, 권장).

G-0. ESXi 의 timeout 문법부터 확인

ESXi 의 timeout 은 버전에 따라 문법이 다르다. 둘 중 되는 것을 쓴다.

timeout -t 1 -s INT true   && echo "형식 A: timeout -t <초> -s INT"
timeout -s INT 1 true      && echo "형식 B: timeout -s INT <초>"
pktcap-uw 의 -G 는 캡처 시간이 아니다

-G 는 파일 회전 주기다. 캡처를 시간으로 끝내려면 반드시 바깥에서 timeout 으로 감싸야 한다.

G-1  ·  옵션만 쓰는 방식
단순한 조건일 때
echo Y | timeout -t 300 -s INT \
  pktcap-uw --dvfilter <filter> --stage pre \
  --ip 10.1.1.10 --tcpport 80 \
  -C 100 -W 5 \
  -o $D/pcap/20-dfw-pre-web01-eth0.pcap
옵션뜻
--dvfilterF-0 에서 찾은 DFW 필터 이름
--stage pre|post DFW 적용 전 / 후. 두 번 떠서 대조한다
--ip · --tcpport필터 옵션. or 조합 불가
-C 100 -W 5파일당 MB · 개수
echo Y |확인 프롬프트를 자동으로 넘긴다
조건이 여러 개면 파일이 폭증한다

or 가 없으니 조합마다 별도 캡처를 돌려야 한다. IP 2개 × 포트 2개면 vNIC 당 4개. vNIC 2개면 8개 파일이 된다.

G-2  ·  tcpdump-uw 로 파이프 권장
복잡한 필터를 쓰고 파일을 하나로
echo Y | timeout -t 300 -s INT \
  pktcap-uw --dvfilter <filter> --stage pre -o - 2>/dev/null \
| tcpdump-uw -r - -w $D/pcap/20-dfw-pre-web01-eth0.pcap \
  -C 100 -W 5 'host 10.1.1.10 and tcp port 80'
이 방식의 장점
  • tcpdump 표현식을 그대로 쓴다 — or, not, 괄호 전부 가능
  • vNIC·단계당 파일 하나 — 파일 폭증이 없다
  • 도구가 FILTER 설정이 있을 때 쓰는 방식이 이것이다

pktcap-uw -o - 로 표준출력에 흘리고, tcpdump-uw -r - 로 받아서 필터링·저장한다.

G-3. pre 와 post 를 같이 — 실제로 쓰는 형태

D=/vmfs/volumes/<데이터스토어>/manual-$(date +%Y%m%d-%H%M%S); mkdir -p $D/pcap
F=nic-2098765-eth0-vmware-sfw.2
EXPR='host 10.1.1.10 and tcp port 80'

for S in pre post; do
  N=20; [ $S = post ] && N=21
  echo Y | timeout -t 300 -s INT \
    pktcap-uw --dvfilter $F --stage $S -o - 2>/dev/null \
  | tcpdump-uw -r - -w $D/pcap/$N-dfw-$S-web01-eth0.pcap -C 100 -W 5 "$EXPR" &
done
wait
ls -la $D/pcap/
반드시 동시에 떠야 한다

pre 와 post 를 따로 뜨면 대조가 안 된다. 같은 패킷을 봐야 하므로 & 로 동시에 띄우고 wait 로 기다린다.
